# Contributing

1. Create a feature branch from the latest `main`.
2. Keep screen work inside the owning page/style/script file.
3. Coordinate before changing shared CSS, mock data fields, or `shared-state.js`.
4. Use fictional data only.
5. Test links, keyboard focus, invalid inputs, full slots, duplicate check-in, status transitions, and a mobile viewport before opening a pull request.
6. Use commit prefixes: `feat`, `fix`, `style`, `docs`, `chore`, or `test`.

Pull requests should describe the changed screens and include the test steps used.
